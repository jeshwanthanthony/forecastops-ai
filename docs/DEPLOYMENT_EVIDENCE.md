# Deployment evidence

ForecastOps AI is a portfolio project with **two distinct deployment environments**:

1. **Production demo (AWS):** a containerized FastAPI + React application running in Docker on an AWS EC2 instance, behind Nginx and HTTPS.
2. **Kubernetes demonstration:** an independent, single-node **kind** (Kubernetes IN Docker) environment that runs the same app image using checked-in manifests. **Kubernetes is not currently hosting the public AWS website.**

This document distinguishes completed actions from integration plans. Secrets, access tokens, private customer sales, and encrypted seller credentials must not be committed here.

### Reproduce AWS verification from EC2

```bash
aws sts get-caller-identity
aws ecr describe-images --region us-east-2 --repository-name forecastops-ai --image-ids imageTag=v1
aws s3api head-object --bucket forecastops-ai-reports-264632269822-us-east-2-an --key reports/test.txt
curl --fail --silent --show-error https://forecastops.jeshwanthanthony.com/api/health
```

The output of `get-caller-identity` should be an *assumed role*, never a pasted IAM access key. The ECR and S3 commands are read-only. The live demo may change independently of the checked-in manifests.

## Kubernetes: reproducible evidence

The repo includes:

- [Deployment manifest](../k8s/deployment.yaml): one replica, container port 8000, readiness and liveness probes, explicit CPU and memory budgets.
- [Service manifest](../k8s/service.yaml): in-cluster service on port 8000.
- [Local Kubernetes instructions](../k8s/README.md): repeatable kind build, deploy, health check and cleanup.
- [Automated Kubernetes smoke test](../.github/workflows/kubernetes-smoke.yml): builds the real container, runs a temporary kind cluster on GitHub Actions, deploys the checked-in manifests and checks the health endpoint.

The manifests were used in a previous local kind development test. For independent repeatable **proof**, open the GitHub Actions workflow run and verify it reports success. Until that workflow is green, treat the automated test as *configured but unverified*, not a successful deployment.

Kubernetes has **not** been deployed to AWS EKS or on the existing EC2 machine. EC2 has only 1 GiB RAM and remains on Docker to avoid additional cost and destabilizing the Square work.
